# Как собрать x2zapret и выпустить обновление

Эта инструкция для разработчика. Для запуска готовой программы сборка не нужна: скачайте установщик или архив со [страницы загрузки](https://github.com/Zuya73/x2zapret/releases/latest).

Версия задаётся в `Directory.Build.props`. Требуемая версия SDK — в `global.json`. Файл решения для IDE — `x2zapret.slnx` в корне репозитория.

## Проверка основной логики

Понадобятся Git, Python 3 и .NET SDK 10. Эти команды работают на Windows и Linux. Выполняйте их из корня репозитория:

```powershell
python tools/import_flowseal_strategies.py --check
dotnet run --project tests/Zapret.Tests -c Release -- .
```

Первая команда проверяет, что каталог профилей соответствует генератору и исходным BAT-файлам. Вторая запускает тесты настроек, подбора профилей, отчётов, восстановления и других частей логики.

## Сборка окна программы

Приложение использует WPF — библиотеку оконного интерфейса Windows. Для полноценной сборки, запуска и проверки окна используйте Windows:

```powershell
dotnet build x2zapret.slnx -c Release
```

## Архив программы и установщик

Нужны Windows, .NET SDK 10, Python 3 и NSIS 3. NSIS — инструмент, который создаёт установщик. Команды выполняются из корня:

```powershell
./build/package.ps1
python tools/generate_installer_files.py
Push-Location build
try {
    & "${env:ProgramFiles(x86)}\NSIS\makensis.exe" installer.nsi
} finally {
    Pop-Location
}
```

Результаты появятся в `artifacts/`: рабочая папка, ZIP для запуска без установки, установщик и подготовленные для него списки файлов. Эти результаты не хранятся в Git.

Пакет не включает старое меню `service.bat`, его помощники, `utils` и `.service`. Проверка `tools/verify_package.py` убеждается, что в комплекте есть файлы для всех профилей, а контрольные суммы модуля обхода совпадают с ожидаемыми.

При обновлении убираются только известные старые файлы из `build/obsolete-files.json`. Чужие файлы в папках пользователя не удаляются вместе с каталогом.

## Готовый EXE для корня репозитория

На Windows выполните:

```powershell
./build/build-root.ps1
```

Будет создан единый EXE со встроенным .NET и значком X2. Для запуска из репозитория ему нужны папки `vendor` и `resources`, но не соседние DLL или установленный SDK.

Автоматическая сборка проверяет такой запуск в отдельной папке с пробелами в пути. После успешной проверки `main` отдельная задача записывает EXE в корень репозитория. Файл `build/root-executable.json` хранит версию, контрольную сумму EXE, сведения об исходниках и коммите сборки. Если входные файлы не изменились, повторного коммита нет.

## Что проверяет GitHub Actions

Процесс **Windows desktop** описан в `.github/workflows/desktop.yml`. Он проверяет профили и файлы Flowseal, собирает решение, архив и установщик, а затем запускает проверки настоящего окна Windows.

Проверяются:

- Размер и положение окна, панель задач, масштабирование 100–200% и восстановление после смены размеров рабочего пространства.
- Переходы между вкладками, сохранение полей и прокрутки, переключатели и отключение анимаций.
- Таймер и его отмена. Компьютер тестовой среды при этом не выключается: используется отдельная отключённая задача.
- Информация о ПК, скрытие личных значений, поиск и сбор всех разделов Windows.
- Запуск, отмена, остановка и перезапуск отдельного процесса чтения датчиков, в том числе при зависании.
- Тест диска: работа с новым временным файлом 256 МиБ, результаты, отмена, очистка и сохранность посторонних файлов.
- Сетевые инструменты: заданные тестовые HTTP-ответы, ограничение трафика, отмена, неполные данные и ICMP-проверка собственного компьютера через loopback. Большие сетевые загрузки для этих проверок не нужны.
- Отображение ячеек и переключение инструментов X2 Tools в обычной сборке и отдельном EXE.
- Установка в папку с пробелами, обновление с прежним именем программы, сохранение настроек и автозапуска, запуск рядом с часами и удаление.

Снимки окна и результаты проверок сохраняются в файлах сборки GitHub Actions. Основной набор называется `x2zapret-Windows-x64`, отдельный EXE — `x2zapret-root-executable`.

Автоматическая проверка не заменяет проверку обхода в реальной сети и на реальном оборудовании. Перед выпуском изменений сетевого модуля проверяйте работу на Windows 10/11, у разных провайдеров, после перезагрузки, при отмене и восстановлении.

## Как публикуется обновление

1. Укажите новый номер в `Directory.Build.props` и соответствующую версию в манифесте приложения.
2. Добавьте понятное описание в `docs/releases/<версия>.md` и обновите инструкции, если изменился интерфейс.
3. Дождитесь успешных проверок запроса на слияние — Pull Request, или PR.
4. Слейте PR в `main`. Обычная автоматическая сборка подготовит выпуск `desktop-v<версия>`.

Сначала файлы загружаются в черновик GitHub Release. Проверяются размер и SHA256 установщика — его контрольная сумма. Затем выпуск публикуется и становится виден клиентам. Уже опубликованную версию не перезаписывают: для новых изменений нужен новый номер.

Ручной выпуск по тегу с совпадающим номером версии тоже поддерживается. Для старых клиентов дополнительно публикуется установщик с прежним именем `Z-zapret`.

**Обновить EXE в `main` недостаточно, чтобы клиент получил обновление.** Программа читает только опубликованные стабильные версии на странице Releases. После публикации автоматическая проверка убеждается, что клиент версии 0.2.2 находит новый установщик.

Старый процесс выпуска Flowseal хранится как справочный файл в `legacy/flowseal/workflows` и не запускается.

## Перенос обновлений Flowseal

Порядок описан в [UPSTREAM.md](UPSTREAM.md). Проверки сравнивают точную версию и коммит Flowseal, повторяют перенос и проверяют правила совместимости. Количество профилей берётся из комплекта, а не фиксируется в коде.

После намеренной замены сторонних файлов пересоздайте список контрольных сумм:

```powershell
python tools/generate_engine_manifest.py
```

GitHub Actions проверяет его с `--check`.

## Где находятся сборщики X2 Tools

| Часть | Файлы и особенности |
| --- | --- |
| Информация о ПК | `Runtime/PcInfo/Collect.ps1`, модели в `Zapret.Core/PcInformation.cs`. Встроенный PowerShell 5.1 получает фиксированную категорию; поиск и пути сохранения не попадают в команды |
| Передача скрипта | UTF-8-скрипт передаётся через стандартный ввод как base64 короткой постоянной команде. Это не превышает лимит командной строки Windows и не зависит от её кодировки |
| Датчики | `HardwareWorker.cs`, `NativeHardwareClient.cs`, `PawnDriver.cs`; статистика — `Zapret.Core/HardwareTelemetry.cs`. LibreHardwareMonitorLib 0.9.6 закреплён в проекте |
| Отдельный процесс | Вызовы библиотеки датчиков выполняются отдельно от окна. Job Object Windows связывает время жизни дочернего процесса с приложением; действуют отмена и ограничение времени ожидания |
| Лицензии | `tools/package_hardware_licenses.py` копирует тексты и сведения о фактически использованных пакетах в комплект. В корневом EXE лицензии встроены |
| Проверка диска | Модели и разбор XML — `Zapret.Core/DiskBenchmark.cs`; временная папка, файл и запуск — `Runtime/DiskBench`. Microsoft DiskSpd из `vendor/diskspd` встроен в EXE |
| Дополнительные инструменты | `MainWindow.ExtendedTools.xaml.cs`, `Runtime/NetworkTools.cs`; модели истории, сети и анализа места — в `Zapret.Core` |

Проверки `--pc-check`, `--hardware-check`, `--disk-check`, `--disk-native-check` и `--extended-tools-check` создают отчёты о результате. Демонстрационные снимки содержат явную подпись примера; показатели на них не выдаются за измерение компьютера пользователя.

Драйвер PawnIO не устанавливается ни проверкой датчиков, ни тестовой установкой x2zapret. Его официальный установщик отдельно проверяется по размеру, SHA256 и цифровой подписи, без запуска. В обычной программе загрузка и установка начинаются только по отдельной кнопке пользователя.

## Старые консольные инструменты

```powershell
./build/package-legacy.ps1
```

Создаётся отдельный `Flowseal-legacy-tools-<версия>.zip`. Он не нужен графическому приложению. Подробнее — в [LEGACY.md](LEGACY.md).
