# Сборка x2zapret

Откройте корневой `x2zapret.slnx` в IDE с поддержкой .NET 10.
Версия продукта задаётся только в `Directory.Build.props`; минимальная линия SDK - в `global.json`.

## Ядро и регрессионные проверки

Из корня репозитория, на Windows или Linux с .NET SDK 10:

```powershell
python tools/import_flowseal_strategies.py --check
dotnet run --project tests/Zapret.Tests -c Release -- .
```

Полная сборка решения включает WPF, поэтому выполняется на Windows:

```powershell
dotnet build x2zapret.slnx -c Release
```

## Приложение и установщик

Нужны Windows, .NET SDK 10, Python 3 и NSIS 3. Команды запускаются из корня:

```powershell
./build/package.ps1
python tools/generate_installer_files.py
Push-Location build
try {
    & "${env:ProgramFiles(x86)}\NSIS\makensis.exe" installer.nsi
} finally {
    Pop-Location
}
```

Результаты находятся в `artifacts/`: каталог приложения, portable ZIP, установщик
и сгенерированные списки файлов NSIS. Эти файлы не хранятся в Git.
Пакет приложения не содержит BAT/PowerShell-сценариев, `utils` и `.service`.
Проверка `tools/verify_package.py` контролирует ресурсы всех импортированных профилей,
обязательные файлы и контрольные суммы движка перед созданием ZIP.

При обновлении установщик удаляет только прежние файлы из `build/obsolete-files.json`.
Удаление каталогов не рекурсивное: посторонние файлы пользователя сохраняются.

## GitHub Actions и выпуск

Workflow `Windows desktop` проверяет импорт стратегий и синтаксис PowerShell,
собирает решение и оба пакета, запускает регрессионные тесты, рендерит WPF,
проверяет установку, обновление, автозапуск и удаление.
Проверка границ окна запускает настоящий WPF в обычном, развёрнутом
и восстановленном состоянии: на текущем рабочем столе и при уменьшенной
рабочей области с резервом под панель задач (подстановка rcWork в том же
обработчике окна; настройки рабочего стола не меняются). Размеры при DPI 100–200%
и расположение панели задач по четырём краям проверяются отдельно.
Отдельный WPF-прогон проверяет быстрые переходы между вкладками, сохранение
форм и прокрутки, переключатели, завершение анимаций и отключение движения.
Промежуточные кадры перехода и результаты сохраняются вместе с артефактами.
Артефакт называется `x2zapret-Windows-x64`.

После успешной проверки main workflow автоматически публикует новую версию
из `Directory.Build.props` как стабильный GitHub Release `desktop-v<версия>`.
Сначала загружаются файлы в черновик и проверяется SHA256 установщика, затем
релиз становится видимым клиентам. Уже опубликованная версия не перезаписывается.
Ручной выпуск по совпадающему тегу также поддерживается. Заметки к версии
можно добавить в `docs/releases/<версия>.md`. Сам EXE в main не является обновлением
для клиента: клиент читает только опубликованные Releases.
Для совместимости с обновлятором 0.1 публикуется копия установщика с прежним именем.
Старый workflow выпусков Flowseal сохранён в `legacy/flowseal/workflows` и не запускается.

## Готовый EXE в корне

`./build/build-root.ps1` собирает сжатый self-contained single-file EXE со значком X2.
.NET находится внутри файла. Для запуска из репозитория рядом нужны только
`vendor` и `resources`, устанавливать SDK пользователю не требуется.
CI проверяет запуск в отдельной папке с пробелами без соседних DLL.
После успешного прогона main отдельная задача записывает проверенный EXE
в корень репозитория. В `build/root-executable.json` сохраняются версия, хэш
EXE и отпечаток исходников. Если приложение не изменилось, повторного коммита нет.

После изменения сторонних бинарников обновите манифест:
`python tools/generate_engine_manifest.py`. CI проверяет его с `--check`.

## Компоненты Flowseal и X2 Tools

Порядок импорта и автоматический PR описаны в [UPSTREAM.md](UPSTREAM.md).
CI проверяет lock-файл, повторный импорт точного upstream commit, правила
совместимости и отсутствие жёсткой привязки к количеству профилей.

Дополнительно выполняются проверки таймера: ввод часов/минут, восстановление,
отмена, принадлежность задачи и схема Task Scheduler. Проверка Windows использует
отключённую задачу с cmd.exe; выключение ПК в тестах не выполняется.


Информация о ПК находится в `src/Zapret.Desktop/Runtime/PcInfo`, её модели,
фильтрация и отчёты - в `src/Zapret.Core/PcInformation.cs`. Сборщик PowerShell 5.1
встроен в EXE как ресурс; скрипт не нужно держать рядом с приложением. Это отдельный
ограниченный по времени процесс: длинный UTF-8 скрипт передаётся через stdin как
base64 короткой постоянной загрузочной команде, поэтому не превышает лимит командной
строки Windows и не зависит от кодовой страницы. Идентификаторы категорий разрешены
только из фиксированного списка; значения поиска и пути сохранения в команды не попадают.

CI `--pc-check` проверяет настоящий WPF, скрытие личных значений, поиск, быстрые
смены категории, сохранность таймера, native CPU/RAM counters и сбор всех 18 разделов
на Windows. Для публичного изображения `pc-information-preview.png` используются
явно подписанные демонстрационные характеристики; сведения Windows runner в изображение
и журнал не выводятся. В receipt сохраняются только количества строк и предупреждений.


Встроенные датчики: `Runtime/PcInfo/HardwareWorker.cs`, `NativeHardwareClient.cs`,
`PawnDriver.cs`; статистика - `Zapret.Core/HardwareTelemetry.cs`. NuGet фиксирует
LibreHardwareMonitorLib 0.9.6. Вызовы SDK изолированы в собственном дочернем процессе
с Job Object, закрытием при уходе и тайм-аутом. Тест `--hardware-check` проверяет
реальный старт, повторное чтение, остановку, перезапуск, отмену и зависший тестовый
процесс. Ни он, ни установочные smoke-тесты не устанавливают PawnIO на CI.
Отдельно проверяется размер/SHA256/Authenticode официального установщика без запуска.

`tools/package_hardware_licenses.py` копирует лицензионные тексты и сведения
о фактически разрешённых NuGet-зависимостях в пакет. Корневой EXE содержит
лицензии как ресурсы. Установщик драйвера не распространяется вместе с приложением:
его скачивает кнопка после явного действия пользователя.
