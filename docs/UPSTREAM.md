# Обновление компонентов Flowseal

Интерфейс, X2 Tools и логика x2zapret находятся в src/ и не копируются из upstream.
Импортируется только стабильный релиз Flowseal/zapret-discord-youtube.

## Что закреплено

- vendor/zapret/upstream.lock.json: версия, точный commit и Git-хэши исходных и
  импортированных файлов.
- vendor/zapret/bin: неизменённые движок, драйвер и пакеты.
- legacy/flowseal: исходные стратегии и вспомогательные сценарии.
- resources/lists: стандартные списки автора.
- resources/catalogs/strategies.json: каталог, сгенерированный из BAT как из текста.
- tools/flowseal-overrides.json: отдельные совместимые исправления legacy-инструмента.
  Если автор изменил нужный участок, импорт требует обновить правило; исправление не теряется.
- resources/catalogs/legacy-seed-hashes.json: отпечатки списков, поставлявшихся с 0.2.4.
  Этот файл не перегенерируется при очередном импорте: он нужен для миграции старых клиентов.

Исходные BAT/PowerShell не исполняются при импорте. Workflow автора, интерфейс
и пользовательские файлы не импортируются. Глобальное слияние upstream/main
с нашим main не требуется. Для исходных файлов отключена нормализация переводов строк.

## Автоматический путь

Workflow Sync Flowseal components проверяет стабильные релизы каждые 6 часов.
Новый релиз создаёт или обновляет ветку upstream/flowseal и PR с описанием версии.
Параллельно запускается полный Windows desktop из этой ветки: сборка, ядро,
интерфейс, установка/обновление/удаление, таймер и контроль файлов.

Результат публикуется на точном commit как Flowseal Windows validation. Это работает
и без запуска PR-workflow через GITHUB_TOKEN. Если GitHub запрещает создание PR
из Actions, остаётся проверенная ветка, а ссылка для создания PR выводится в summary.
При необходимости разрешите создание PR в Settings → Actions → General.

После проверки и слияния PR в main обычная сборка выпускает новую версию
x2zapret, установщик, готовый EXE в корне и стабильный Release для клиентов.
Импорт автоматически поднимает patch-версию приложения; выпущенные версии не заменяются.
Непроверенная upstream-ветка не публикует установщики или EXE в main.

## Ручной воспроизводимый путь

Из корня репозитория с Git и Python:

~~~bash
python tools/sync_flowseal.py --tag 1.10.4 --check
python tools/sync_flowseal.py --bump-version
python tools/verify_upstream.py
python tools/import_flowseal_strategies.py --check
python tools/generate_engine_manifest.py --check
~~~

Первая команда проверяет закреплённый снимок без изменений.
Вторая импортирует последний стабильный релиз. Для выбора версии добавьте
--tag X.Y.Z. Перед импортом используйте отдельную ветку с чистым рабочим деревом.
Повторный импорт той же версии не создаёт изменений. Изменение уже существующего
тега, неизвестные переменные в стратегиях, повторяющиеся имена, неожиданные
пути или несовместимое правило исправления останавливают импорт для проверки.

## Совместимость на компьютере пользователя

Неизменённые файлы движка обновляются с проверкой всего входного комплекта.
При ошибке замены ранее изменённые файлы откатываются. Если запущена наша служба,
она останавливается на время обновления и запускается с актуальным профилем.
Чужие службы не останавливаются.

Стандартные списки имеют отдельный журнал исходных хэшей. Ручные изменения и
четыре пользовательских списка не перезаписываются. Новый вариант изменённого
стандартного списка сохраняется рядом как .upstream.
