# Как переносить обновления Flowseal

Эта инструкция для тех, кто обновляет исходный код x2zapret. Обычный пользователь получает проверенные файлы Flowseal вместе с новой версией приложения.

**Upstream** здесь означает исходный проект `Flowseal/zapret-discord-youtube`. Из него берутся модуль обхода, профили и стандартные списки. Наш интерфейс, X2 Tools, логика и пользовательские данные остаются отдельными.

## Что сохраняется о каждой версии

| Файл или папка | Для чего нужен |
| --- | --- |
| `vendor/zapret/upstream.lock.json` | Точная версия Flowseal, коммит и контрольные суммы исходных и перенесённых файлов |
| `vendor/zapret/bin` | Файлы модуля обхода, драйвера и служебных пакетов без изменения содержимого |
| `legacy/flowseal` | Исходные профили и вспомогательные консольные сценарии |
| `resources/lists` | Стандартные списки Flowseal |
| `resources/catalogs/strategies.json` | Каталог профилей, который создаётся чтением BAT-файлов как текста |
| `tools/flowseal-overrides.json` | Точные правила наших исправлений совместимости для старых инструментов |
| `resources/catalogs/legacy-seed-hashes.json` | Контрольные суммы списков из версии 0.2.4; нужны для обновления старых установок |

Последний файл **не пересоздаётся при каждом переносе**. Иначе программа не сможет отличить старый стандартный список от пользовательских изменений.

BAT и PowerShell-сценарии при переносе не запускаются. Процессы GitHub Actions автора и его пользовательские файлы не копируются. Сливать целиком `upstream/main` с нашим `main` не требуется. Исходные файлы сохраняют переводы строк без автоматического преобразования.

## Автоматическое обновление исходников

Процесс **Sync Flowseal components** проверяет стабильные выпуски каждые 6 часов. При появлении новой версии он:

1. Создаёт или обновляет ветку `upstream/flowseal`.
2. Переносит нужные файлы и увеличивает последнюю часть версии x2zapret.
3. Создаёт запрос на слияние — Pull Request, или PR, с описанием изменений.
4. Запускает полный набор **Windows desktop** для этой ветки: сборку, проверку окна, установку, обновление, удаление и остальные проверки программы.

Результат с именем **Flowseal Windows validation** привязывается к точному коммиту. Это нужно, в частности, потому что PR от `GITHUB_TOKEN` не всегда запускает обычный процесс проверки PR.

Если GitHub не разрешает автоматическому процессу создать PR, проверенная ветка остаётся доступной, а ссылка на создание PR появляется в итоговом отчёте запуска. Разрешение на такие PR настраивается в **Settings → Actions → General**.

После успешной проверки PR нужно слить в `main`. Тогда обычная сборка выпустит новую версию приложения, установщик, архив и EXE в корне. Само появление непроверенной ветки Flowseal не публикует обновление пользователям.

## Ручной перенос

Нужны Git и Python. Работайте в отдельной ветке; перед началом сохраните текущие изменения в коммите. Команды выполняются из корня:

```bash
python tools/sync_flowseal.py --tag 1.10.4 --check
python tools/sync_flowseal.py --bump-version
python tools/verify_upstream.py
python tools/import_flowseal_strategies.py --check
python tools/generate_engine_manifest.py --check
```

Первая команда проверяет повторный перенос версии 1.10.4 без изменения файлов. Вторая переносит последний стабильный выпуск и увеличивает версию приложения. Чтобы выбрать другую версию явно, добавьте `--tag X.Y.Z`.

Перенос той же версии не должен создавать новые изменения. Если исходный тег у автора теперь указывает на другой коммит, встречены неизвестные параметры, повторяющиеся имена, неожиданные пути или несовместимое правило исправления, процесс останавливается. Проверьте причину вручную; не обходите проверку простым обновлением контрольных сумм.

Описания профилей задаются в `tools/import_flowseal_strategies.py`. Если меняете только формулировки, сохраняйте идентификаторы профилей, исходные файлы и аргументы запуска.

## Как сохраняются настройки пользователя

Перед заменой проверяется весь входящий комплект файлов обхода. Если замена не удалась, уже изменённые файлы возвращаются. Наша работающая служба останавливается на время обновления и запускается с доступным профилем. Чужие службы не останавливаются.

Неизменённые стандартные списки можно обновить. Четыре пользовательских списка и ручные изменения не перезаписываются. Новый вариант изменённого стандартного списка сохраняется рядом с расширением `.upstream`, чтобы его можно было сравнить самостоятельно.

Если прежний профиль или служебный пакет больше не входит в комплект, выбирается доступная замена, а старые настройки сохраняются в резервной копии.

## Если номер версии уже занят

Пока PR ожидал слияния, в `main` могла выйти другая версия. Проверка не позволит выпустить изменённые файлы под уже опубликованным номером.

Повторно запустите **Sync Flowseal components**: ветка будет создана на актуальном `main` и получит следующий свободный номер. Опубликованные файлы прежней версии остаются неизменными.
